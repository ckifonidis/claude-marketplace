# Migrate agent-step 2.5.0 → 2.6.0

> Severity: additive. Applied by `/pull-library`; readable standalone.

## What changed

One addition: the runner now keeps a per-task audit record of what every admitted batch actually
did, in a new library-managed, task-scoped **`actionTrail`** slot. `run/finalize.ts` appends one
entry per step RESULT — domain steps, controls, and the synthetic `auto_handoff` alike — in
execution order:

```ts
// state.ts (new exports: TrailEntrySchema, TrailEntry)
actionTrail: TrailEntry[] | null
TrailEntry = { action: string; ok: boolean; error?: string; proposed?: boolean }
```

- `error` carries the step result's error code (gate refusals, prereq denials, `invalid_params`,
  `executor_error`, host verdict codes). `proposed: true` marks a confirmation propose/re-propose
  (no executor ran), distinguishing it from the later execute entry of the same action name.
- The projection is an ALLOW-LIST: never params, summaries, or result bodies — the trail is
  PII-free by construction.
- Boundary invariants (all test-pinned in the new `trail.test.ts`): an **admission-refused batch
  leaves no trail** (nothing admitted, nothing committed — the refusal invariant extends to the
  trail); **execution-phase refusals ARE recorded** with their error codes; an executor writing the
  slot through `stateUpdate` **throws** (it joined `LIBRARY_MANAGED_KEYS`); the slot is
  **task-scoped** (`agentStepTaskScopedSlots`) — a `completed`/`abandon` handback clears it, so
  each task on a reused thread starts a fresh trail. Forced handoffs (`HandoffSpec.forcedHandoff`)
  never reach the runner and never appear.
- **Audit-only.** Nothing in the runner, the controls, or the model surface reads it — the
  model-facing schema is byte-identical to 2.5.0. Consumers read it from observability's
  graph-state capture; the complete per-task record lives in the INPUT state of the
  `resolve_handoff` run (the node clears task-scoped slots in its output).
- The slot rides the spread fragments (`agentStepZodShape` / `agentStepStateSpec`) and joins
  `agentStepInternalSlotMask` (eight → **nine** keys), so a mask-derived graph input schema keeps
  rejecting it at the invoke boundary with no host edit.
- One `requiredManagedChannels` change: `actionTrail` is the first **unconditionally required**
  channel — the trail is written on every finalized batch regardless of which features the config
  uses, so construction now throws if the host state schema lacks the channel. A host that spreads
  the exported fragments (the only supported pattern) always has it.

## Why

The handback wire is a ROUTING vocabulary: task-ending outcomes collapse into
`completed`/`abandon`, so auditing could not distinguish "the operation persisted" from "the
caller cancelled at the last gate" — and a voluntary mid-task cancellation left no record of how
far the caller got, because no executor runs on a cancel. Host outcome slots exist but each agent
names and shapes its own, so no cross-agent view was possible. The runner already sees every
admitted step and its result; recording that projection at the one layer every agent shares gives
uniform audit visibility with zero per-agent declaration work.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit; recursive). **One file is added**: the top-level `trail.test.ts`. For a host on the
scaffold pattern (state spreads the fragments; input schema derives from the mask), the library
replacement IS the whole upgrade.

## Manual follow-ups

- **Audit consumers** read the trail from the `resolve_handoff` run's INPUT state in the
  observability stream — the node's output clears task-scoped slots, and the thread's final state
  is not the record. Turns on dropped calls (no handback) still carry the partial trail on the
  tool node's run events.
- **Run filtering:** a deployment with `KAFKA_RUN_FILTER_MODE=allow` must keep patterns matching
  the tool node's runs (and `chain:resolve_handoff`), or the state that carries the trail never
  reaches the sink. Filter mode `off` (the default) needs nothing.
- No prompt work: the model never sees the slot, and the model-facing surface is unchanged —
  prompt goldens and prompt-input fixtures need no re-pinning.
