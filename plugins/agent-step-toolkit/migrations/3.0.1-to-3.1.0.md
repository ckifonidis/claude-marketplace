# Migrate agent-step 3.0.1 → 3.1.0

> Severity: additive. Applied by `/pull-library`; readable standalone.

## What changed

One optional field on `HandoffSpec`, the configuration `createHandoffNode` already reads:

```ts
interface HandoffSpec<T> {
  // …unchanged fields…
  onHandback?: (state: T, request: HandoffRequest) => void | Promise<void>;
}
```

The resolver node calls it once per handback — `completed`, `abandon`, `off_topic`, and the
terminate fallback after a delegate failure; never after a successful delegate, which is not a
handback — with:

- the **EFFECTIVE** request (after any `resolveHandoffType` override), and
- the state **before** `clearsOnHandback` and the library's task-scoped clears — the same view
  `resolveClosingMessage` chose the spoken closing from.

It is an **observer**: it runs after the reply, the signal and the metadata are final; it is called
synchronously but never awaited; a throw or a rejected promise is contained. It returns nothing the
node reads and cannot write state. The final message, its `additional_kwargs`, the custom events and
the returned clears are byte-identical with or without it.

```ts
// handoff-spec.ts — a host recording the contact's outcome (the set-pin agent's shape)
export const handoffSpec: HandoffSpec<State> = {
  offTopic: { mode: "terminate" },
  terminateMessage: required("HANDOFF_TERMINATE_MESSAGE"),
  resolveClosingMessage: closingFor,
  onHandback: (state, request) => {
    const outcome = outcomeFor(state, request); // the same reading the closing uses
    if (outcome) recordContact(outcome, state); // starts in the background, never throws
  },
};
```

## Why

Some endings run no host executor at all — an exhausted escalation ladder (`captureBounces`,
`note_refusal`) or the auto-handoff over a thrown executor — so the resolver node is the only place
that sees every ending. A host that had to record the outcome could only wrap the node (which the
design principles forbid: "nothing wrapped") or hide I/O inside the pure `resolve*` functions. Same
precedent as `resolveHandoffMetadata` / `clearsOnHandback`: the library takes the job so hosts stop
reopening what it owns.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit). Changed files: `handoff/contract.ts` (the field), `handoff/node.ts` (the call),
`handoff.test.ts` (four new tests), `VERSION`.

This release is additive-only: **no `<transforms>` and no per-tool edits are needed** — the library
replacement alone is the upgrade. A spec without `onHandback` behaves exactly as in 3.0.1.

## Manual follow-ups

- A host that wraps `createHandoffNode` (or patches its result) only to run a side effect after the
  handback can move that side effect into `onHandback` and drop the wrapper.
- `onHandback` cannot write state. A side effect that must happen exactly once at a moment that may
  NOT end in a handback (e.g. a success followed by a question the caller can hang up on) belongs in
  the executor that decides it, not here.
