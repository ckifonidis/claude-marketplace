# Migrate agent-step 3.1.0 → 4.0.0

> Severity: **breaking**. Applied by `/pull-library`; readable standalone.

## What changed

4.0.0 settles who owns each sentence and removes the configuration that existed to work around the
old answer.

1. **Two registers, visible on the wire.** Every string the ENGINE emits is a model-facing
   `instruction` it owns outright (`engine-text.ts`) — English, never spoken verbatim, never
   overridden. Everything a CALLER can hear is rendered by the HOST from state and rides `summary`,
   `read_back` or `ask_text`. A result entry carries one or the other:

   ```jsonc
   // 3.1.0 — an engine refusal
   { "action": "verify_card", "ok": false, "summary": "…", "error": "invalid_params" }
   // 4.0.0
   { "action": "verify_card", "ok": false, "instruction": "…", "error": "invalid_params" }
   ```

   `RunnerResultBody.summary` is optional and `RunnerResultBody.instruction` mirrors a batch that
   ended on an engine entry. The `messages` build option, `SystemMessages`,
   `DEFAULT_SYSTEM_MESSAGES` and `resolveSystemMessages` are gone. Hosts extend engine frames
   through structured seams only: `GateContractSpec`, the new `AskContractSpec`
   (`buildAgentStepTool({ askContract: { categories } })`) and `toolTurnRules`.

2. **Standing asks live on the row that asks.** `ActionDef.asks` and `DictationAsk` are removed:

   ```ts
   // 3.1.0
   asks: {
     not_a_name:     { action: "collect_full_name", param: "fullName",     expects: "text" },
     invalid_params: { action: "collect_full_name", param: "fullName",     expects: "text" },
     ask_for_digits: { action: "verify_card",       param: "spokenDigits", expects: "digits" },
   },

   // 4.0.0 — on the verdict rows
   verdicts: {
     not_a_name:     { ok: false, summary: …, body: { verdict: "not_a_name" }, ask: "self" },
     ask_for_digits: { ok: false, summary: …, body: { verdict: "ask_for_digits" },
                       ask: { action: "verify_card" } },
   },
   ```

   `param` defaults to the target's sole capture field, `expects` is derived from that field's
   kind, and the `invalid_params` re-ask is derived from the bouncing action's own capture — it is
   no longer declared anywhere.

3. **Params declare what they are.** The capture builders register a machine-readable kind:
   `digits` (`callerDigits`, `digitGroupsParam`, `digitCandidatesParam`), `text`
   (`callerTextParam`), `judged` (new `judgedEnum` / `judgedFlag`), `relay` (`relayParam`). Only
   `digits` and `text` are ask targets. A value-shape keyword in a model-facing params schema
   (`pattern`, `minLength`, `maxLength`, `format`) now fails construction — shape rules are
   refinements.

4. **Bounded patience is universal.** `ladders`, `captureBounces`, `CaptureBouncePolicy`,
   `EscalationLadder`, `LadderRegistry` and `SpentLadders` are removed. One latch, two counters,
   both reset on progress: two consecutive unusable captures bounce plainly, the next one earns one
   in-place explanation, and the turn after that hands back `abandon` on the structural context
   `agent-step:escalated:<action>`. `note_refusal` takes a semantic kind:

   ```jsonc
   // 3.1.0
   { "action": "note_refusal", "params": { "ladder": "digits_declined" } }
   // 4.0.0
   { "action": "note_refusal", "params": { "kind": "declined_or_cannot" } }
   ```

   Kinds: `declined_or_cannot`, `unsupported_question`, `malicious_intent`. The third
   `malicious_intent` in a task hands back `completed` on `agent-step:malicious`.

   The counts above are the DEFAULTS of four process-wide **tolerances**. Nothing is declared per
   action, per tool or in a prompt; a deployment may move the numbers through environment variables
   the engine itself reads, once, when the tool is built:

   | Variable | Default | Range |
   |---|---|---|
   | `AGENT_STEP_BOUNCE_TOLERANCE` — plain bounces before the engine explains itself | 2 | ≥ 0 |
   | `AGENT_STEP_FREE_EXPLANATIONS` — explanations before the handback | 1 | ≥ 0 |
   | `AGENT_STEP_MALICIOUS_LIMIT` — the misuse attempt that ends the task | 3 | ≥ 1 |
   | `AGENT_STEP_ERROR_HANDOFF_THRESHOLD` — backend-failure batches before the auto-handoff | 3 | ≥ 1 |

   Unset or blank means the default; a value that is not a plain integer in range throws at
   construction. An explicit `errorHandoffThreshold` option still wins over its variable. No
   model-facing text carries a count, so moving a tolerance changes behaviour and no wire byte.

5. **Handoff closings are host-rendered, always.**

   ```ts
   // 3.1.0
   terminateMessage: required("HANDOFF_TERMINATE_MESSAGE"),
   resolveClosingMessage: (state, request) => closingFor(state) /* string | undefined */,

   // 4.0.0 — required and TOTAL; nothing the engine or the model authors is spoken
   resolveClosingMessage: (state, request) => {
     if (request.context === AUTO_HANDOFF_CONTEXT) return closings(state).technical;
     if (request.context.startsWith(ESCALATION_CONTEXT_PREFIX)) return closings(state).escalated;
     if (request.context === MALICIOUS_CONTEXT) return closings(state).malicious;
     return closingFor(state) ?? closings(state).generic; // the unconditional last row
   },
   // delegate mode only:
   delegateFailureMessage: (state) => closings(state).transfer,
   ```

6. **Smaller moves.** `Verifier.denial` is `{ instruction, error }`; `refuseProposal` returns
   `{ verdict, data? }` naming a declared row; `ActionDef.invalidatesOnChange` becomes the
   config-level `AgentStepConfig.invalidations`; `ProtocolSurface` drops `ladders`; `runSteps`
   validates the configuration; `_debug` leaves the `ToolMessage` content for its `artifact`.

7. **Added, opt-in.** `ActionDef.satisfies` (state-satisfied inputs, with the resolved bundle as an
   optional third executor argument), `ActionDef.bounceCapture`, `DigitGroupsParamOpts.normalize`,
   `repeat_pending_question` over a standing ask with a rendered `ask_text`, and the `AGENT_STEP_*`
   tolerance variables with `resolveTolerances` / `TOLERANCE_ENV` / `DEFAULT_TOLERANCES` (point 4).

## Why

The `messages` override mixed two registers in one bag: half its defaults were finished caller
sentences documented as localizable, while the same family was specified as model-facing and never
spoken. Hosts translated strings that could not be selected. The asks map could name a code no row
emits, could not let two rows sharing a wire code ask differently, and silently cleared the standing
question on a capture bounce when an action forgot its `invalid_params` entry. Named ladders shared
one allowance between unrelated entry points, so a caller who stumbled on one value lost the guided
re-ask for the next. Each fix removes a place where two hand-kept facts had to agree.

toolkit). No per-file action needed — this section just records what moved: added `engine-text.ts`,

`run/satisfies.ts` and the test files `engine-text`, `escalation`, `tolerances`, `field-kinds`,
`declare-hardening`, `satisfies`; removed
`messages.ts`, `capture-bounce.test.ts`, `note-refusal.test.ts`.

## Manual follow-ups

- **Re-measure the model.** The model-facing bytes changed — every engine refusal, the composed
  protocol prompt, the `note_refusal` schema, the `request_handoff` description. Run the live
  prompt-input suites and compare against the pre-upgrade baseline before trusting the upgrade; a
  green offline suite does not cover this.
- **Closings for the engine's endings.** Decide the caller wording for an escalated capture (per
  action where a specific reassurance helps), for the technical auto-handoff, and for the
  `malicious_intent` termination. The channel that ends the call must act on `completed` with
  `handoff_reason` `agent-step:malicious`; check the middleware does.
- **`handoff_reason` now carries codes** for engine-decided endings (`auto_handoff`,
  `agent-step:escalated[:<action>]`, `agent-step:malicious`). A middleware or report that displayed
  it as prose needs a mapping.
- **Ladder wording you relied on.** A ladder's custom `instruction` has no equivalent, and neither
  does a PER-LADDER free-use count: the counts are deployment-wide now.
- **Non-default counts.** If a removed ladder or `captureBounces` policy used a count other than
  the defaults (two plain bounces, one free explanation), decide whether the deployment sets the
  matching `AGENT_STEP_*` variable — knowing it applies to every action alike, and that the
  defaults are the measured values (three plain bounces was seen to make the model improvise on the
  third identical failure). Moving a tolerance owes its own live measurement.
- **Tests that count turns.** A sandbox or unit test that loops "two bounces, then the explanation"
  should take its numbers from `resolveTolerances()` rather than literals, so it passes under any
  environment; a test pinned to the exported constants assumes the variables are unset.
- **`satisfies`** is optional. Adopt it where an action re-asks for a value the state already
  carries (a carried identity, an authenticated session); it replaces hand-rolled probe modules and
  carried-value prompt flags.
- **Test harnesses**: `runSteps` now validates, so a fixture config that was never buildable (a
  missing state channel, an ask to a non-capture param, an action with no rows) fails at its first
  call. Fix the fixture.
