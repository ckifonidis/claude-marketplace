# Migrate agent-step 3.1.0 → 3.2.0

> Severity: behaviour-changing (gate budgets) + additive (tool-free counter). Applied by
> `/pull-library`; readable standalone.

## What changed

### 1. Gate budgets are task-scoped

`requiresConfirmation.maxAttempts` and `requiresMatch.maxAttempts` are no longer refunded by
`abort_pending_input` or by re-running the capturer. What the task has spent is kept in
`spentLadders["confirm:<action>"]` / `spentLadders["match:<consumer>"]`:

| Event | Before | 3.2.0 |
|---|---|---|
| propose after an abort | `attempts_left = maxAttempts` | `maxAttempts − spent` |
| capturer re-run / re-open after abort | `attempts_left = maxAttempts` | `maxAttempts − spent mismatches` |
| execute / successful match | — | clears the latch |
| budget spent, `handoff` configured | plain error, next call starts fresh | error + atomic handoff (`onExhaust`, default `abandon`) |
| budget spent, no `handoff` | plain error, next call starts fresh | unchanged |

Two optional fields name the escalation route (engine-only, like a ladder's):

```ts
requiresConfirmation: { maxAttempts: 3, onExhaust: { reason: "abandon", context: IDENTIFICATION_DEAD_END } }
requiresMatch: { capturer: "capture_pin", maxAttempts: 3, onExhaust: { reason: "abandon", context: PIN_DEAD_END } }
```

### 2. `countToolFreeReply`

One new export, called by the host — the runner does not use it:

```ts
import { countToolFreeReply, type ToolFreeReplyPolicy } from "./agent-step/index.js";

countToolFreeReply(state, reply, { max, onExhaust }); // → { exhausted, patch }
```

It bounds the caller turns the model answers with **no tool call**:

- a reply that carries tool calls ends the run;
- the text that closes a tool turn (the message before it is a tool result) is neutral;
- any other reply is counted under `spentLadders["turn:tool_free"]`; the turn after `max` in a row
  returns `exhausted: true` and a patch that requests `onExhaust` — the same atomic handoff a spent
  ladder applies.

## Why

**Gate budgets.** `attempts_left` lives on the transient `awaitingInput` slot. A read-back answered
with a bare "no" is routed to `abort_pending_input`, which clears the gate, and the next dictation
proposed with the full budget again. Nothing executes, so no host counter moves either: «no» → new
value → «no» … had no cap (reported 2026-11-17, fleet-wide).

**Tool-free replies.** Every bound the runner owns (`captureBounces`, the ladders, a gate's `attempts_left`, `errorCount`)
advances inside a tool batch. A model that stops calling the tool stops being counted: on 2026-11-16
a caller dictating card digits got the same "I didn't catch those digits" reply 26 turns in a row
with no call behind it, and only left the loop by asking for a human.

## Manual follow-ups

**Gate budgets.** Read each confirm-gated action's reply contract with the new arithmetic in mind: a
caller gets `maxAttempts + 1` proposals per action per task whether they correct the value in the same
breath or say "no" first. If a host kept its own interim counter for this (e.g. a proposal counter
checked in `refuseProposal`), it can go. An in-flight thread upgraded mid-gate keeps its open gate's
`attempts_left`; the latch starts counting from the next stored proposal.

**Tool-free counter.** It does nothing until the host wires it. This is a design choice per agent, so
`/pull-library` surfaces it instead of applying it:

1. **Model node** — after the model call, fold the patch into the node's update. On exhaustion
   return the patch WITHOUT the model's reply; the resolver speaks the closing.

   ```ts
   const response = await model.invoke(buildPrompt(state));
   const idle = countToolFreeReply(state, response, TOOL_FREE_POLICY);
   if (idle.exhausted) return idle.patch;
   return { messages: [response], ...idle.patch };
   ```

2. **Edge after the model node** — check the handoff before the tool calls:

   ```ts
   handoffRequested(state) ? HANDOFF_NODE : hasToolCalls(state) ? "tools" : END
   ```

3. **Pick `max`** — it counts every tool-free caller turn, including a legitimate "one moment,
   please". Set it well above `captureBounces.max`; an agent that answers questions in plain text by
   design needs a higher value or should not wire the counter at all.

4. **Streaming** — tokens of the dropped reply have already reached a token-streaming client when
   the handoff is decided, so the caller may hear that reply followed by the closing.

The state needs the `spentLadders` channel (spread `agentStepZodShape` / `agentStepStateSpec`), and
no ladder may be named `turn:tool_free`.
