# Migrate agent-step 4.1.1 → 4.2.0

> Severity: **additive** — nothing is removed or renamed, and a 4.1.1 project compiles unchanged.
> An AUTO-mode project needs the library replacement only. A REQUIRED-mode project
> (`config.tool.toolChoice: "required"`) has one behaviour change to absorb — a standing ask now
> ends the turn's calls — and one decision to make: whether to wire the streamed spoken answer.
> Transforms 1–2 are checks; transforms 3–5 are an opt-in rewrite that must be offered, not applied
> silently. Applied by `/pull-library`; readable standalone.

## What changed

### 1. The spoken answer (required mode — opt-in host wiring)

In 4.1 a required-mode caller turn that ran a workflow step made TWO tool calls: the step, then a
`respond_to_caller` call presenting its result, delivered whole once the second call finished. In
4.2.0 the library offers a third agent-node step instead. When the turn's result awaits the caller,
the next model invocation has calls switched off and its plain text streams:

```ts
// 4.1 — src/agent.ts, the agent node
const reply = completedReply(messages);
if (reply) return { messages: [reply] };
const bound = model.bindTools(modelToolsForTurn([...tools], messages) as never, modelToolOptions(myConfig));
const response = await bound.invoke(buildPrompt(state), { tags: ["langsmith:nostream"] });
return { messages: [toolOnlyMessage(response)] };
```

```ts
// 4.2.0 — the same node with the spoken answer wired
const reply = completedReply(messages);
if (reply) return { messages: [reply] };
if (speechOwed(messages)) {
  const speaker = model.bindTools(modelToolsForSpeech([...tools], messages) as never, speechToolOptions());
  const spoken = await speaker.invoke(buildPrompt(state));          // NO nostream tag: it streams
  return { messages: [spokenMessage(spoken)] };
}
const bound = model.bindTools(modelToolsForTurn([...tools], messages) as never, modelToolOptions(myConfig));
const response = await bound.invoke(buildPrompt(state), { tags: ["langsmith:nostream"] });
return { messages: [toolOnlyMessage(response)] };
```

| Helper | What it does |
|---|---|
| `speechOwed(messages)` | true when the latest result of this caller turn says `continuation: "await_caller"` |
| `modelToolsForSpeech(tools, messages)` | the surface to bind — the scoped surface a fresh caller turn sees |
| `speechToolOptions()` | `{ tool_choice: "none" }` — tools visible, no call possible |
| `spokenMessage(response)` | the response as the node's message; throws on a tool call or empty text |

The graph, its edges and the prompt are unchanged. A turn that only speaks, and the presentation of
a result that carries no `continuation`, still go through `respond_to_caller` and are still
delivered whole by `completedReply`.

**What the wiring trades away.** A reply made through `respond_to_caller` has its fixed text
(`read_back`, `ask_text`, `reply_text`) inserted and checked by the engine. A spoken answer does
not: the model transcribes those bytes and nothing verifies them. A host that leaves the step out
keeps the 4.1 behaviour exactly — engine-checked text, no streaming. Both are supported.

### 2. A standing ask ends the turn's calls (required mode — every project)

Until 4.1.1 a result that left a standing ask carried no `continuation` unless it was an
`invalid_params` bounce, and the model could make a second call in the same caller turn — typically
to send a value the caller had already volunteered. Now every final entry that carries
`standing_ask` or `ask_text` is stamped `continuation: "await_caller"`:

```ts
// 4.1.1
{ action: "start", ok: true, summary: "…", standing_ask: { action: "identify", param: "number" }, ask_text: "…", ask_contract: "…" }
// 4.2.0 (required mode)
{ action: "start", ok: true, summary: "…", standing_ask: { action: "identify", param: "number" }, ask_text: "…", ask_contract: "…",
  continuation: "await_caller" }
```

A second call after such a result is refused with `error: "continuation_required"` unless it is the
speech step. A volunteered value rides the SAME batch as the step that asks for it —
`[start, identify { number }]` — and the result then leaves no ask standing. There is no opt-out: a
row with an `ask` may declare no continuation other than `"await_caller"`. Auto mode is unchanged.

### 3. A verdict row can open the next consent — `proposes` (optional, both modes)

```ts
verdicts: {
  ok: {
    ok: true,
    summary: "…",
    proposes: { action: "close_account", params: (state, data, params) => ({ /* … */ }) },
  },
}
```

When the executor returns that row, the engine appends the named action's proposal to the same
result — read-back, attempts, lockdown, reply contract — and drops any steps batched after it. Only
on a plain `ok: true` row; the target must be confirm-gated.

### 4. Judged params outside the consent — `consentExempt` (optional, both modes)

```ts
requiresConfirmation: { readBack, consentExempt: ["flagged"] }   // `flagged` is a judgedFlag / judgedEnum param
```

The listed params are ignored when a re-call is matched against the pending proposal. On the
execute, one the re-call omits takes the stored proposal's value; one it supplies wins.

### 5. What the channel sees (required mode with the spoken answer wired)

| Frame from node `agent` | Shape |
|---|---|
| the tool call | one consolidated AI message, empty content — as in 4.1 |
| a spoken answer | a token stream: one empty chunk, the text chunks, two empty chunks, one message id |
| a delivered reply | one whole chunk with a fresh message id — as in 4.1 |

A middleware that speaks non-empty content from node `agent` as it arrives, and ignores empty
content, needs no change.

### 6. Known issues shipped with 4.2.0

None is fixed in this version; design around them (`agent-step-api.md` `<known_issues>`).

- A spoken answer is not checked against the result's fixed text.
- `consentExempt` carries a judgement forward on the execute only — not across a re-proposal, and
  not across `abort_pending_input` plus a fresh proposal.
- A proposal opened by `proposes` always starts with the target's full `maxAttempts`
  (reachable only with `lockdown: false`).
- A row may propose its own action; construction does not reject it.
- Params from `proposes.params` that the target's schema rejects read as a failed caller capture.
- `spokenMessage` reads string content only.

## Why

Time to first audio. In 4.1 the speech after a workflow step was the argument of a second tool
call, tagged `langsmith:nostream`, so the caller heard nothing until that whole call finished. With
the result deciding that the next invocation can only speak, the model's own text can stream — and
`proposes` plus the standing-ask boundary keep the turn at one tool call before it.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit). No per-file action needed — this section records what moved in the library itself.

- `reply.ts` — adds `speechOwed`, `speechToolOptions`, `modelToolsForSpeech`, `spokenMessage`; the
  wiring header describes the three-step agent node.
- `index.ts` — exports the four helpers.
- `types.ts` — `VerdictDef.proposes`, `ConfirmationOpts.consentExempt`.
- `compile/validate.ts` — the three new construction checks.
- `interaction/confirmation.ts` — `consentExempt` in the gate's normalized options and in the
  proposal match.
- `run/planning.ts` — on an execute, exempt params the re-call omitted are filled from the proposal.
- `run/execution.ts` — the `proposes` splice.
- `run/finalize.ts` — the standing-ask stamp (required mode).
- `proposes.test.ts` — new, 7 tests. Library suite: 364.

## Manual follow-ups

- **Decide the wiring, per host.** Streaming against engine-checked text is a product decision.
  A sentence that must be exact more than it must stream can stay on the control: a
  `presentation: "verbatim"` row that does NOT declare `continuation: "await_caller"` is still
  presented through `respond_to_caller` and checked.
- **Pin spoken consent text in the prompt-input layer.** Once the spoken answer is wired, nothing
  in the engine checks it. For every consent question — a proposal's `read_back`, a rendered
  `ask_text`, a verbatim `reply_text` — play the turn that produced it and assert the fixed bytes,
  several runs each.
- **Volunteered values.** Look for prompt text or tests that rely on the model sending a value in a
  second call after a standing ask; it now has to arrive in the same batch as the step that asks.
- **Rows that should stream.** Only a result that ends in `"await_caller"` is spoken as a stream. A
  row whose outcome is simply told to the caller, and that declares no continuation, still costs a
  second tool call and arrives whole; declare `continuation: "await_caller"` on it if it should
  stream.
- **The channel middleware.** Confirm it handles both reply shapes — a whole chunk and a token
  stream bracketed by empty chunks (`/audit-middleware-contract-compliance`, item 9).
- **`proposes` and `consentExempt` are design choices**, not migrations: adopt them where a
  confirmed capture always leads to the same consent, and read the known issues first — in
  particular, a judgement that must survive a correction belongs in state, not only in proposal
  params.
- **Re-measure.** A required-mode project that wires the spoken answer owes its live suites and a
  streamed conversation run before it ships.
