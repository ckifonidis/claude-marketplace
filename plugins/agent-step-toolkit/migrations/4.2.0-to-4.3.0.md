# Migrate agent-step 4.2.0 → 4.3.0

> Severity: **behaviour-changing, no code change required** — nothing is removed or renamed and a
> 4.2.0 project compiles unchanged. A project WITH a handoff configured and a confirm- or
> match-gated action gets bounded gate budgets by replacing the library. Transform 1 is a check;
> transforms 2–3 are checks on tests and the closing table; transform 4 is an opt-in rewrite for
> AUTO-mode projects that must be offered, not applied silently. Applied by `/pull-library`;
> readable standalone.

## What changed

### 1. Gate budgets are task-scoped (handoff configured)

In 4.2.0 a confirmation's `attempts_left` lived only on `awaitingInput`. `abort_pending_input`
cleared it, so the next proposal opened with the full `maxAttempts`: a caller answering every
read-back with a bare "no" and a new value was never bounded. The match gate refunded the same way
on an abort or a capturer re-run.

In 4.3.0 the runner also records what the task has spent in `spentLadders`
(`confirm:<action>`, `match:<consumer>`):

| Event | 4.2.0 | 4.3.0 (handoff configured) |
|---|---|---|
| fresh proposal after `abort_pending_input` | `attempts_left = maxAttempts` | `maxAttempts − spent` |
| proposal opened by a row's `proposes` | `maxAttempts` | `maxAttempts − spent` |
| capturer re-run / re-open after abort | `attempts_left = maxAttempts` | what is left (min 1) |
| budget spent | plain `confirmation_attempts_exhausted` / `match_attempts_exhausted` | same `error`, plus `escalated`, `handoff_requested`, `reason: "abandon"`; handoff on `escalationContext(action)` |
| refund | abort, re-capture | an execute / a successful match only |

Without a handoff configured nothing changes.

### 2. `countToolFreeReply` (auto mode, opt-in)

A host helper that counts consecutive caller turns the model answered with no tool call and, past
`max`, returns the escalation handoff patch (`abandon`, `escalationContext(null)`). A project in
required mode (`tool.toolChoice: "required"`) does not need it.

## Transforms

1. **Check — nothing to rewrite.** Replace `src/agent-step/` and run `npm run typecheck`.
2. **Check — tests that pin a refund.** Search the project's tests for an `attempts_left`
   assertion that follows an `abort_pending_input` or a capturer re-run in a THREADED conversation
   (state carried between `runSteps` calls) on a config with `handoff`. Such a pin now sees the
   reduced budget; update the expectation. A test that hand-builds `awaitingInput` without
   `spentLadders` is unaffected.
3. **Check — the closing table.** `resolveClosingMessage` already receives
   `escalationContext(<action>)` for a spent explanation. Confirm the confirm- and match-gated
   action names are covered by the table (or its prefix fallback on `ESCALATION_CONTEXT_PREFIX`).
4. **Opt-in — wire the tool-free counter (auto mode only).** Offer, do not apply silently:

```ts
// src/agent.ts — the model node, auto mode
import { countToolFreeReply } from "./agent-step/index.js";

const response = await bound.invoke(buildPrompt(state));
const { exhausted, patch } = countToolFreeReply(state, response, { max: 6 });
if (exhausted) return patch;                       // no reply — the resolver speaks the closing
return { ...patch, messages: [response] };
```

   and route `handoffRequested(state)` to `HANDOFF_NODE` on the edge after the model node, before
   the tools/END decision. `max` counts every tool-free caller turn, legitimate ones included — keep
   it well above `AGENT_STEP_BOUNCE_TOLERANCE`.

## Verify

`npm run typecheck && npm test` — the library suite is 377 tests.
