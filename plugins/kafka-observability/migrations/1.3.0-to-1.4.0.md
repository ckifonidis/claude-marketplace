# observability library 1.3.0 → 1.4.0

Redaction-precision release. The sensitive-key pattern's `token` substring was masking
every LLM usage counter (`tokenUsage`, `prompt_tokens`, `completion_tokens`,
`input/output_tokens`, `*_token(s)_details`, …) — found live during the 1.3.0 QA
verification (400+ `***REDACTED***` usage fields across one verified thread), killing all
cost/usage analytics downstream. 1.4.0 adds two carve-outs in `redaction.ts`: values that
cannot carry a secret (numbers, booleans, null) pass verbatim whatever their key, and the
known usage containers recurse normally instead of being masked whole (their contents
still fully redacted). The credential key pattern is untouched; sensitive-keyed strings
and non-exempt sensitive-keyed objects are masked exactly as before.

Pure file refresh — no project-level wiring, env, or deployment change. Two deliberate
payload-content changes (both restore intended LangSmith parity):

- LLM usage counters and usage containers now appear in events verbatim (previously
  `***REDACTED***`).
- `null` under a sensitive key (e.g. `password: null`) passes as `null` (previously the
  redaction marker). Numbers/booleans under sensitive-substring keys likewise pass.

<transforms>

**1. No file transforms.** Library files are replaced wholesale; `.env.example` and
deployment settings are unchanged (no new env vars).

**2. Advisory (not a transform): re-verify at payload level.** After re-vendoring, run one
real conversation and confirm in the sink that (a) `usage_metadata`/`tokenUsage` fields
carry numbers, not `***REDACTED***`, and (b) a spot-check of credential-shaped keys
(`api_key`, `authorization`, SASL fields in `serialized`) still shows the marker.

**3. Advisory (not a transform): downstream analytics.** Token-usage percentile stats
become computable from events produced AFTER this version; events produced by ≤1.3.0
carry the marker permanently — backfill is not possible from the pipeline. Consumers
should treat `***REDACTED***` in usage fields as "predates 1.4.0", not as data.

</transforms>
